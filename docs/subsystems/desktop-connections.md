# Desktop Connections

Connections separates profile-owned messaging channels, chat-specific tool connectors, and the background gateway. It uses the same capability cards and progressively disclosed controls as Models & providers and media settings.

Telegram distinguishes absent configuration from an intentionally disabled channel. A configured channel is labeled Connected only when the gateway is running and fresh polling evidence is healthy. Bot verification, allowlists, pairing, protected credentials, and review/apply retain their existing controls. Telegram setup groups bot credentials and access settings into separate sections. Review remains explicit before saving; a confirmed save closes setup and shows a dismissible confirmation on Connections. An uncertain save keeps its inspection action available and never retries automatically. No setup action sends a message without its separate explicit action.

Connector inspection remains bound to the selected chat. Manage reveals the existing chat-wide reconnect action; it does not imply individual connector reconnection. Status reasons are bounded categories, never raw connector errors, commands, or credentials. Disabled connectors remain distinct from unavailable connectors.

The gateway checks service/runtime metadata on entry, every five seconds, on window focus, and when opening Manage. Start is shown for an installed stopped service; Stop and Restart are visible for a running installed service. On macOS, an unloaded job with an installed profile plist remains installed, so stopping does not require reinstalling. Detailed diagnostics remain under Advanced & diagnostics. Install/start/stop/restart still require explicit review, and the interface reconciles the last durable operation before mutation. Unknown or uncertain outcomes block another lifecycle action; status checks do not repeat commands. Closing Desktop does not stop the gateway.

Security note: these are presentation and read-only metadata changes over the existing profile-bound, reviewed setup and lifecycle paths. They do not broaden messaging authorization, install authority, workspace trust, private-site access, or cloud-spend permission. Installation metadata does not prove a user service's current auto-start configuration, so the interface makes no auto-start claim.
