## Security review and limits

This is a security-sensitive change across runtime, tools, approvals, ACP, gateway and Task execution. Current denial and hardline checks precede grants. Scope is generated by core code, never model input. Authorization generations are independent of target generations. Metadata-only changes do not churn reusable grants; revocation invalidates in-flight authorization even after an identical regrant.

Grant JSON remains the source of truth. The lock database is a write mutex, not a second authority store. Interrupted mutations release their transaction lock; unknown formats and unsafe mutation paths fail closed. Back up stopped-process state before upgrade. Older binaries can discard new binding/revision fields, so downgrade requires a compatible snapshot.

B08 is closed. B09 is closed for local/channel grant scope and generation; recurring workflow authorization remains PR 5. These changes neither implement exclusive Session execution across processes nor terminate work already dispatched. B01/B02/B04 still require PR 4. Host facts explicitly make no containment, credential filtering or aggregate resource enforcement claim; host process ownership and lifecycle remain PR 3. Managed multi-tenant infrastructure still requires those later boundaries.

## PR 1 / PR 2 review follow-up

The subsequent implementation review found four gaps: a dangling registry symlink was accepted; exact-action tokens could expire before their approvals; unrelated grant mutations fenced covered work; and stale CLI-approved channel continuations could repeatedly stop approval processing. A focused correction addresses all four without advancing PR 3 or PR 4 scope.

- Registry initialization uses `lstat` even when a link's destination is absent, and a regression verifies no destination database is created.
- Pending actions retain opaque identities through their own expiry. Task links retain them for the configured approval lifetime and release their own retention on consumption, denial or terminal closure. Cache pressure cannot evict retained identities; changed arguments, expired approvals and consumed approvals remain gated. Process restart still requires renewed exact-action review.
- Approval JSON version 3 separates the storage revision from scoped revocation revisions. Revocation records survive removal and regrant. Final dispatch also checks that the specific persistent grant still exists with its original generation and authority. Version 2 scoped grants remain usable, and version 1 records remain unscoped and inactive.
- Stale channel continuations are removed with one renewal message. Tests cover revocation, expiry and unavailable scope while another chat's approved work continues.

Security review: existing hardline, trust, Session ownership, expiry and one-time consumption gates remain intact. JSON remains the authority store and the existing SQLite transaction remains its write mutex. Retention is process-local and bounded; it does not confer execution authority. Upgrade writes version 3 on mutation; older binaries must not write the upgraded state. Use the existing stopped-process backup/downgrade procedure.

Validation uses a fresh isolated checkout of tracked files plus this correction, preserving unrelated operator files.
