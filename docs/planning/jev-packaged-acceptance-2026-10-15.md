A new skill with missing setup still prevents a completion claim.

## Follow-up: live delivery and recovery correction

With a working GPT route, all three live workers and synthesis completed, but delivery exposed two runtime defects: the research prohibition removed local readers because they shared the `research` toolset, and save-only recovery exhausted the no-progress guard before read-back. The file existed but had not been verified by the runtime.

The focused correction:

- Distinguishes network research activity from shared local result/file readers when applying explicit research prohibitions. Exact tool prohibitions remain binding, including dotted names. “Researcher” is a skill name, not an affirmative research verb.
- Treats an empty optional discovery ID list as an omitted filter. Exposure requests still require nonempty valid IDs and pass the existing session, budget and authorization boundaries.
- Credits new queued recovery receipts, new accepted-result page coverage, and requested file versions/read-backs while checkpoint projection catches up. Repeated IDs, repeated page coverage, denied/failed calls and cached reads do not count. No iteration limit was increased.
- Preserves explicitly invoked skills used “to explain” or “to describe,” without turning the explanation into file execution. Negative need statements do not create research obligations. An explicitly requested skill can provide guidance from supplied facts even when its usual activity is prohibited; its tools still respect the activity prohibition. Inherited checkpoint skills do not receive this exception.
- Reports binary, empty and narrowly recognized challenge-page fetch responses as extraction failures rather than source evidence. This is not a PDF parser or a general CAPTCHA detector; usable HTML/text extraction and URL policy are retained.
- Describes an unverified file as unverified, rather than asserting it was never saved.

Risk review: changes affect selection, tool-result interpretation and completion progress. They grant no new execution authority. Workspace/profile scoping, approvals, URL restrictions, exposure limits and actual write/read-back requirements remain unchanged. Regression tests cover rejection and duplicate-progress cases alongside successful recovery.
