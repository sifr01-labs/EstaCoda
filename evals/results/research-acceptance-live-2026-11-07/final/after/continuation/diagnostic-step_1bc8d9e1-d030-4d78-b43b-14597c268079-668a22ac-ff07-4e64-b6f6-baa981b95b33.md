## Authorization findings

### Defaults and admission model

This implementation governs **incoming-work admission, assessment outcomes, and mandate revalidation**. It is not a generic tool-level filesystem, shell, or network permission engine.

Source policy defaults to an empty allowed list and empty admission table; policy sources default to `{}`. Evaluation defaults to **`observe`**, not `auto`, and paused defaults to false (`upstream/superagent/src/policy.ts:74-87`, `upstream/superagent/src/policy.ts:99-104`).

| Sender/message relationship | Default admission |
|---|---|
| Listed, addressed | Explicit, outside the admission table |
| Listed, unaddressed | Inferred |
| Unlisted, addressed | Ignore |
| Unlisted, unaddressed | Ignore |

Reference: `upstream/superagent/src/admission.ts:1-13`.

Only an unlisted **addressed** admission cell may grant explicit authority. Unaddressed cells permit only inferred or ignore (`upstream/superagent/src/policy.ts:74-77`).

An empty allow list therefore does not grant universal access, but membership is not the sole admission basis: configured table cells and participating-thread follow-ups can admit unlisted senders.

### Precedence: no global deny-overrides-allow rule

For human triggers, the gate evaluates:

1. Listed sender addressing the agent → explicit.
2. Admission cell granting explicit → explicit.
3. Qualifying participating-thread follow-up → explicit for listed senders, inferred for others.
4. Inferred admission cell, with evaluation mode not off → inferred.
5. Otherwise reject.

Reference: `upstream/superagent/src/policy.ts:191-210`.

Consequences:

- An `ignore` cell does **not** veto a listed sender’s addressed request.
- An `ignore` cell does **not** veto a qualifying thread follow-up.
- Explicit table admission precedes follow-up classification, avoiding a downgrade from explicit to inferred.
- Unlisted direct-message senders cannot use the follow-up branch, although an explicit direct-message table cell can separately admit them.

Tests intentionally encode these choices (`upstream/superagent/tests/policy.spec.ts:102-114`, `upstream/superagent/tests/policy.spec.ts:137-152`).

### Scope and identity matching

- Identity lookup selects the allowed list using **`actor.source`**. It does not map a person across sources (`upstream/superagent/src/policy.ts:119-126`).
- Matching uses case-insensitive string equality—not wildcards, regexes, prefixes, or roles. Both allowed-human and listed-bot lookup use the same helper (`upstream/superagent/src/infra/text.ts:18-19`; `upstream/superagent/src/policy.ts:119-126`).
- Listening and observation are delegated to `SourceScope.scope`. Its returned row selects admission overrides; missing rows or cells fall back to defaults (`upstream/superagent/src/policy.ts:130-141`).
- Unaddressed table admission requires a listened and observed scope (`upstream/superagent/src/policy.ts:199-201`).

**Integration boundary:** the human gate does not universally reject `listened: false` before its addressed and follow-up branches. A listed/addressed human returns immediately, and qualifying follow-ups have no direct listened check. Machine admission and mandate revalidation explicitly check listening (`upstream/superagent/src/policy.ts:172-178`, `upstream/superagent/src/policy.ts:191-207`, `upstream/superagent/src/policy.ts:216-219`).

This warrants caller analysis; it is **not proof of a reachable authorization bypass**. Upstream trigger filtering was outside this investigation.

### Assessment, confirmation, and approval

`assessmentOutcome` requires:

- Exactly one judgment for every enabled rule, without duplicate, missing, disabled, or unknown IDs.
- A valid direction establishing implementation intent, a determined target, and no remaining design decision.
- At least one matched rule.
- Truthy `intent_evidence`.

An inferred acceptance outside auto mode becomes `ignore` with an audited `would_accept` proposal. Explicit acceptance is not blocked by evaluation mode (`upstream/superagent/src/policy.ts:18-29`, `upstream/superagent/src/policy.ts:40-60`).

There is **no confirmation-token exchange, human approval queue, or reviewer-signoff state machine implemented in this file**. Rule instructions may specify reviewers and waiting for approval, but this layer represents that as instruction text (`upstream/superagent/src/policy.ts:66-69`). Observe mode records proposed acceptance; it is not itself an approval workflow.

The validator does not independently establish that direction, intent evidence, or supplied rule judgments are factually correct (`upstream/superagent/src/policy.ts:25-29`, `upstream/superagent/src/policy.ts:40-60`).

### Risk classifications and special cases

- The operative classifications are **explicit, inferred, and ignore**, not low/medium/high risk.
- Default enabled rules concern copy fixes and tightly constrained visual fixes. The visual instruction excludes redesign, new behavior, and unsettled targets through prose constraints, not a quantitative risk classifier (`upstream/superagent/src/policy.ts:62-65`).
- Named nonhuman actors must appear on their source’s bot list. Bots receive inferred status at most, require listened and addressed-or-observed reception, and are blocked when evaluation is off.
- Senderless events require the `unlistedUnaddressed` cell to grant inferred admission and evaluation mode not off (`upstream/superagent/src/policy.ts:172-188`).
- Executor blocked-command configuration defaults empty, constrains command-name syntax, and prevents blocking selected worker commands. Actual command-execution enforcement is not implemented here (`upstream/superagent/src/policy.ts:88-98`).

### Revalidation and security limitations

Revalidation checks receiving scope, bot membership, current admission strength, evaluation mode, and matched-rule enablement according to mandate basis (`upstream/superagent/src/policy.ts:213-244`).

Important qualifications:

- After the recorded-scope check, **explicit follow-ups remain valid without renewed allowed-sender membership checks**.
- Inferred follow-ups require auto mode and enabled recorded rules.
- `rulesOn(undefined)` and `rulesOn([])` succeed vacuously, whereas `admitsInferred([])` fails. Stronger invariants depend on mandate construction; this does not establish externally injectable mandates (`upstream/superagent/src/policy.ts:212`, `upstream/superagent/src/policy.ts:220-222`).
- Pause is exposed as a property rather than enforced inside `gate`; consumers must honor it (`upstream/superagent/src/policy.ts:189-191`).
- Policy version hashes rules, mode, and policy-source settings, but excludes operational source configuration. Scope changes therefore cannot rely solely on version equality (`upstream/superagent/src/policy.ts:111-118`).
- `policyEffects` reports rule changes, requester authorization loss, and proactive-work cessation; it does not itself terminate workers (`upstream/superagent/src/policy.ts:143-165`).
