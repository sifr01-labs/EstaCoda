## Strengths, tradeoffs, and benchmark implications

**Supported strengths:** composable host services; explicit event boundaries; cancellation/error recovery; durable child creation/resume paths; separate permission/confinement concepts; replay-aware compression; namespaced MCP tools; filesystem skills; typed API and usage infrastructure.

**Tradeoffs:** plugin availability is not application enablement; composition increases lifecycle complexity; native-backed persistence requires platform-ready artifacts; fork seeds preserve context but require measuring inherited token cost; model-free pruning bounds volume but may remove useful middle content.
