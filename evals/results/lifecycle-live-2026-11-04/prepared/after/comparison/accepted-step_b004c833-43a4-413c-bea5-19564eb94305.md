## Correctness limitations and realistic tradeoffs

1. **No selected test failed.** Source-observed weaknesses should not be misrepresented as demonstrated regressions.
2. **Recovery trades availability for safety.** Uncertain non-idempotent operations can require review; uncertain provider dispatch can retain spending capacity rather than automatically refund it.
3. **Verification depends on declared scope and observed changes.** The runtime explicitly does not calculate a complete dependency graph for each declared check.
4. **Memory has lower-level persistence boundaries worth auditing.** `hydrate` bypasses the write-time budget check and file saving is not visibly atomic at that layer. Higher-level services may add controls; this review does not establish universal guarantees.
5. **Governed autonomy has operating costs.** Trust decisions, approvals, result acceptance, durable service wiring, and skill review complicate deployment while addressing failure modes that lightweight agent loops may leave to operators.
6. **Host execution and worktrees are not security isolation.** Docker is a separate configured backend with prerequisites, not an assumed default.
